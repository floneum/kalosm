WHAT THE BETTER TOOLS EXPOSED
1. Semantic dispatch profiling ties every executed shader body to its real
   matrix shape, quantization, schedule, grid, and timestamp. Group/slab launches
   preserve their members; no invented division of a composite's GPU duration.
   The analyzer verifies body IDs, launch indices, grids and complete coverage.
2. The dominant original prompt operation is fused gate/up projection:
   M=16, N=28672, K=4096, Q4_K. It consumes 39.4% of per-dispatch-profiled GPU
   time: 1373 ms, 416 launches. The candidate uses M=128 and takes 524 ms in
   64 launches (37.2% of its faster prompt). This is the worthwhile target,
   unlike the earlier visually striking reductions that totaled under 1%.
3. Column-major weights already had adjacent global loads, but staging wrote
   a transposed pattern to shared memory. The new layout keeps that staging
   contiguous and loads the cooperative B fragment with the transpose flag.
   Complete matrix tiles also avoid redundant clamped/masked loads. Partial
   tiles retain bounds checks and remainder lanes remain guarded.
4. Larger batching/tiling alone, with the original staging compiler, measured
   1.980x prompt GPU improvement (model-ab.json). Adding the staging change
   brings the controlled result to 2.327x. The staging optimizations were tested
   together; these numbers do not separately attribute transpose versus masking.
5. Host-stage timings expose initial plan selection as the startup problem.
   A representative candidate cold extraction spends 6.455 s in seed selection,
   30.3 ms in bounds, 12.3 ms in local search, 4.5 ms deriving the plan. Setting
   FUSOR_MOVE_WORK=0 does not avoid this seed work (seed-only.log). The initial
   selection sweep, which reprices candidate DAGs, is the next CPU target.
6. After this change, attention Sgemm operations M=512, K=128, batch=8, N=128
   or 256 consume another 216 ms (15.3% of candidate prompt GPU time). They
   reach only about 57–67 effective GFLOP/s in this profile; inspect their layout
   and family selection next. This is a measurement, not a promised speedup.

DISCARDED HYPOTHESES
Increasing K tiles to 64/128 did not produce a consistent gain; some schedules
fell back to Sgemv or slowed dramatically. Their domain expansion was reverted.
The earlier combined trial is retained only as staging-experiment.patch.
Q4_K packed nibble spacing suggested a 128-element lane gap. Batched command
replay showed the original gap-32 cell at 294 us versus the best gap-128 trial
near 304 us for M=1,N=28672,K=4096. No decode win. The default domain is unchanged;
explicit debug pins can now request a legal non-default gap.
Single cold/idle microbenchmark submissions overstated decode costs by roughly
3x. Use LAB_BATCH_REPEAT=32 for this throughput experiment; steady-gap-* holds
those measurements. Replays run only this lab's pure matrix graph, while its
uniforms and arena are live. Never replay a stateful KV-cache graph this way.

TIMING METHOD AND LIMITS
The GPU completes compute before timestamps are resolved in a separate submission.
Same-submission Metal timestamp probes from the earlier investigation were invalid
and are not used. Whole-plan timing supplies the headline A/B. Per-dispatch
instrumentation has extra GPU/host overhead, so its absolute totals differ;
use baseline.summary.json and optimized-semantic.summary.json for attribution,
not mixed-mode speedup arithmetic. Operand-byte counts are logical native-format
volume, not physical DRAM traffic, cache misses, or a bandwidth lower bound.
Online exploration was disabled. Actual selected families are logged: a pinned
Coop domain does not force extraction to choose Coop. Tuning and lowering can
produce kernels that are not the final inference plan.

Full numerical A/B, with a new output directory:

The preserved reference executable is local to this investigation. To repeat on
another machine, save an executable before changing contract.rs, then pass its
path as PROFILE_REFERENCE_BINARY. Both binaries must include the profiling
example and logit-capture feature. Without that override, the script compares
batching configurations using the current compiler in both arms. It refuses
existing logit directories, validates full numerical results and GPU coverage,
and fails if prompt GPU speedup is below 2x (PROFILE_MIN_GPU_SPEEDUP overrides).

LAB_OUTPUT_DIR saves full little-endian f32 outputs. Full tensors remain local
and git-ignored; compact correctness summaries and compressed dispatch logs are
reviewable. The stepwise virtual GPU still does not interpret cooperative-matrix

those kernels without pretending the simulator can execute them.

TAIL-SHAPE FOLLOW-UP
The wide Q4_K tail experiment did complete and passed its CPU checks for
M=63,64,65 and N=28673,K=4096. M=63 and 64 used Coop. At M=65 the selector
switched to Sgemv, taking about 129 ms versus 5 ms at M=64; the pinned Coop
domain creates a severe padding/family-selection cliff. That particular run
left cold autotuning enabled: its 204-second cold setup and warm numbers are
diagnostic only, not a controlled A/B. The lab now requires disabling autotuning
for batched replay and enables timing only for the controlled replay. The earlier
steady-gap sweeps already disabled autotuning and remain valid.
The 64x64 pin is a measured configuration for the tested 128-token prompt path,
not a universal tile policy for arbitrary matrices.
